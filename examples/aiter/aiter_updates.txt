AITER kernel changes and alternatives
=====================================

The RockBuilder AITER patch series changes four runtime kernel families.
Some changes add architecture-specific implementations, while others port
existing kernels to GPUs that previously could not compile or execute them.

New or newly ported kernel paths
-------------------------------

1. Quick All-Reduce FP8 Support (module_quick_all_reduce)

   - Module:
     - module_quick_all_reduce
   - Kernels:
     - allreduce_prototype_twoshot
     - allreduce_rmsnorm_prototype_twoshot
   - GPU support:
     - gfx90a uses the HIP E4M3-FNUZ conversion path.
     - gfx1100 uses software E4M3-FNUZ conversion.
     - gfx1201 retains native packed FP8 conversion.
     - Existing native conversion paths remain available on supported newer GPUs.
   - Testing:
     - Use op_tests/validation/validate_quick_reduce_fp8_conversion.cu for
       standalone HIP conversion accuracy.
     - Use op_tests/validation/validate_quick_reduce_fp8_multigpu.py for
       multi-GPU PyTorch accuracy.
     - Compare the result against torch.distributed.all_reduce.
     - Compare speed against generic custom, symmetric-memory, and RCCL
       all-reduce paths with HIP event timing.
     - Standard vLLM does not select Quick Reduce on gfx1100 or gfx1201 because
       its high-level policy currently restricts Quick Reduce to MI300 systems.

2. Wave Split-K FP8 GEMM Support (module_custom)

   - Module:
     - module_custom
   - Operation and kernels:
     - wvSplitKQ
     - wvSplitKQ_hf_
     - wvSplitKQ_hf_sml_
     - wvSplitKQ_rdna_
     - wvSplitKQ_partial_
     - wvSplitKQ_reduce_
   - GPU support:
     - gfx90a uses packed wave64 FNUZ decoding, caches activation tiles in
       LDS, uses 512-thread blocks for large output-column shapes, and
       provides a branch-free reduction specialization for 16 splits.
     - gfx1100 uses wave32 OCP decoding and caches activation tiles in LDS.
     - gfx1200 and gfx1201 use wave32 OCP decoding without LDS caching.
     - gfx942 and gfx950 retain the existing native CDNA path.
   - Testing:
     - Use testing/module_custom/wvsplitkq_compare.cu for the interactive or
       environment-selected legacy, split-K, rocBLAS, and CPU comparison.
     - Use op_tests/validation/validate_gfx90a_wv_split_kq.py on gfx90a.
     - Use op_tests/validation/validate_rdna_wv_split_kq.py on gfx1100,
       gfx1200, or gfx1201.
     - Compare accuracy against dequantized FP32 PyTorch matrix multiplication.
     - Add HIP event timing and compare performance against matching CK and
       Triton FP8 GEMM configurations.

3. Fused QK RMSNorm Quantization Support (module_fused_qk_rmsnorm_group_quant)

   - Module:
     - module_fused_qk_rmsnorm_group_quant
   - Kernel:
     - fused_qk_rmsnorm_group_quant_kernel
   - Public operations:
     - fused_qk_rmsnorm_group_quant
     - fused_qk_rmsnorm_per_token_quant
   - GPU support:
     - gfx90a uses the existing CDNA arithmetic and HIP FP8 conversion.
     - gfx1100 uses scalar FP32 multiplication and software FP8 conversion.
     - gfx1201 uses scalar FP32 multiplication and native FP8 conversion.
     - The module remains available across configured CDNA and RDNA targets.
   - Testing:
     - Use op_tests/test_fused_qk_rmsnorm_group_quant.py for accuracy and
       performance testing.
     - Compare accuracy against PyTorch RMSNorm followed by explicit
       quantization.
     - Compare speed against separate AITER operations and
       Triton fused_mxfp8_quant where the output formats match.

4. Plain TopK Wave32 Support (module_topk_plain)

   - Module:
     - module_topk_plain
   - Kernels:
     - topk_sort_kernel
     - topk_filter_kernel
     - topk_merge_kernel
   - GPU support:
     - gfx90a, gfx94x, and gfx950 use the existing wave64 path.
     - gfx11xx, including gfx1100, use the new wave32 sort and merge path.
     - gfx12xx and gfx1250, including gfx1201, use the new wave32 path.
   - Testing:
     - Use op_tests/test_topk_plain.py for combined accuracy and performance
       testing.
     - The test already compares AITER against torch.topk and Triton and
       reports timing and speedups.
     - Compare values and index sets for accuracy, with special handling for
       tied values.

Alternative implementations
---------------------------

The alternatives below provide comparable functionality, but they are not
always drop-in replacements. Layout requirements, fusion, communication
protocols, quantization formats, and performance can differ.

MIOpen is not involved in these implementations or their fallback selection.
These operations concern collective communication, specialized inference GEMM,
quantization, and selection rather than MIOpen's neural-network operator set.

Related filter-only changes
---------------------------

- module_chunk_gdr_fwd_h keeps its HIP implementation on gfx90a, gfx94x,
  gfx950, gfx1200, and gfx1201. gfx1100 is routed to its Triton fallback.
- The A8W8, DeepGEMM, Opus MoE, MXFP4, VSA, CK2, and gfx1250 all-reduce
  patches filter unsupported modules or select existing fallbacks. They do
  not add new kernel families.
